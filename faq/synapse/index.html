Synapse FAQ

Common questions about capabilities, deployment model, data handling, Jira sync behavior, and support.

Install from Atlassian Marketplace Product page Contact support

What does Synapse do?

Inside Jira (Forge Issue Panel), Synapse generates requirements previews and test-ready artifacts from Jira issue context.

Transcript processing is available only in Synapse SaaS deployments (if enabled), with review workflows before Jira sync.

What runs where?

  • Forge: Jira app surface, scoped auth, and app workflow orchestration.
  • SynapseWorks backend: Scoped backend service via Forge Remote.
  • Jira Cloud: Source and destination for issue-linked artifacts.

The Jira app path uses Forge plus a scoped backend service via Forge Remote.

How is data handled?

In Jira (Forge Issue Panel), Synapse generates from Jira issue context. Transcript processing is available only in Synapse SaaS deployments (if enabled).

Jira credentials and personal access tokens are not stored.

If you are evaluating a demo environment, confirm any session-only handling details with support before sharing sensitive content.

Jira permissions and sync behavior

  • Access uses Forge appUserToken with scopes read:jira-work, write:jira-work, and read:app-user-token.
  • Writes should be reviewed with your Jira permission model before production rollout.
  • Sync actions are designed to be repeatable; validate idempotent behavior in your staging project for your configuration.

Forge vs SaaS

  • Inside Jira (Forge): issue-context generation, refine editor, dry-run validation, and create subtasks where enabled.
  • Outside Jira (SaaS, deployment-dependent): transcript ingestion, review workflow, and idempotent Jira sync.

What are the limits?

LLM-assisted outputs can contain omissions or inaccuracies. Teams should treat outputs as drafts and apply human review before implementation or release decisions.

Roadmap disclaimer

Capabilities may change as Atlassian platform features and customer requirements evolve. Roadmap details are directional and not a delivery commitment.

Support

Email support@synapseworks.org. Include your Jira Cloud site URL, issue keys, expected vs actual behavior, and timestamps.

Security posture

Credentials: No Jira credentials or personal access tokens are stored.

Architecture: Forge app with a scoped backend service via Forge Remote.

Flow: Jira → Forge → scoped backend service via Forge Remote → Forge/Jira.
